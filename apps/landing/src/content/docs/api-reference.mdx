# API Reference

The Orchestra REST API provides programmatic access to all project management, interview orchestration, task execution, and provider credential management features.

**Base URL:** `http://localhost:3000`

## Authentication

API endpoints do not require authentication by default. Provider credentials are managed through dedicated endpoints and encrypted at rest.

## Error Format

All errors follow a consistent structure:

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable description of the error"
  }
}
```

### Error Codes

| Code | HTTP Status | Description |
|------|-------------|-------------|
| `NOT_FOUND` | `404` | Requested resource does not exist |
| `VALIDATION_ERROR` | `400` | Request body or parameters failed validation |
| `RATE_LIMITED` | `429` | Too many requests — slow down |
| `OVER_BUDGET` | `403` | Usage has exceeded the configured budget limit |
| `CIRCUIT_OPEN` | `503` | Provider circuit breaker is open — service temporarily unavailable |
| `INTERNAL_ERROR` | `500` | Unexpected server error |

## Health & Readiness

### GET /health

Returns the health status of the server.

```
GET /health
```

**Response:**

```json
{
  "status": "ok"
}
```

### GET /ready

Returns the readiness status including database connectivity.

```
GET /ready
```

**Response:**

```json
{
  "status": "ok",
  "database": "connected"
}
```

| `database` value | Description |
|------------------|-------------|
| `"connected"` | Database is available and responsive |
| `"not_configured"` | No database has been configured |
| `"disconnected"` | Database connection has been lost |

## Projects

### GET /api/v1/projects

List all projects with pagination.

```
GET /api/v1/projects?page=1&limit=20
```

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `page` | `number` | `1` | Page number |
| `limit` | `number` | `20` | Items per page |

**Response:**

```json
{
  "data": [
    {
      "id": "proj_abc123",
      "name": "My Project",
      "ideaText": "A brief description of the project idea...",
      "createdAt": "2025-01-15T10:30:00Z",
      "updatedAt": "2025-01-15T10:30:00Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 42,
    "totalPages": 3
  }
}
```

### GET /api/v1/projects/:id

Get a single project by ID.

```
GET /api/v1/projects/proj_abc123
```

**Response:**

```json
{
  "id": "proj_abc123",
  "name": "My Project",
  "ideaText": "A brief description of the project idea...",
  "createdAt": "2025-01-15T10:30:00Z",
  "updatedAt": "2025-01-15T10:30:00Z"
}
```

**Errors:** `NOT_FOUND` (404)

### POST /api/v1/projects

Create a new project from an idea.

```
POST /api/v1/projects
Content-Type: application/json
```

**Request Body:**

```json
{
  "ideaText": "Build a task management app with real-time collaboration",
  "projectName": "TaskFlow"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `ideaText` | `string` | Yes | Free-text description of the project idea |
| `projectName` | `string` | No | Optional project name (auto-generated if omitted) |

**Response:** `201 Created`

```json
{
  "id": "proj_abc123",
  "name": "TaskFlow",
  "ideaText": "Build a task management app with real-time collaboration",
  "createdAt": "2025-01-15T10:30:00Z",
  "updatedAt": "2025-01-15T10:30:00Z"
}
```

**Errors:** `VALIDATION_ERROR` (400)

### DELETE /api/v1/projects/:id

Delete a project and all associated data.

```
DELETE /api/v1/projects/proj_abc123
```

**Response:** `204 No Content`

**Errors:** `NOT_FOUND` (404)

## SSE Progress

### GET /api/v1/progress/:workflowId

Subscribe to real-time progress updates for a long-running workflow via Server-Sent Events.

```
GET /api/v1/progress/wf_gen_001
Accept: text/event-stream
```

**SSE Event Types:**

| Event | Description |
|-------|-------------|
| `progress` | General progress update with percentage |
| `step_start` | A new step has begun |
| `step_complete` | A step has finished successfully |
| `step_error` | A step has encountered an error |
| `token` | Streaming token for LLM output |
| `complete` | Workflow completed successfully |
| `error` | Workflow failed with an error |
| `cancelled` | Workflow was cancelled by the user |
| `heartbeat` | Keepalive ping to maintain connection |

**Example SSE stream:**

```
event: step_start
data: {"step": "analyzing_requirements", "message": "Analyzing interview responses..."}

event: progress
data: {"percent": 25, "step": "analyzing_requirements"}

event: token
data: {"text": "Based on the interview responses, "}

event: step_complete
data: {"step": "analyzing_requirements"}

event: progress
data: {"percent": 50, "step": "generating_architecture"}

event: complete
data: {"result": {"blueprintId": "bp_001"}}
```

### POST /api/v1/progress/:workflowId/cancel

Cancel a running workflow.

```
POST /api/v1/progress/wf_gen_001/cancel
```

**Response:**

```json
{
  "workflowId": "wf_gen_001",
  "status": "cancelled",
  "cancelledAt": "2025-01-15T11:02:00Z"
}
```

**Errors:** `NOT_FOUND` (404)

> [!TIP]
> The SSE connection automatically sends `heartbeat` events every 15 seconds to prevent proxy timeouts.

## Phase Resolution

### GET /api/v1/phases/:planId/resolve

Resolve the current phase and next actionable task for a plan.

```
GET /api/v1/plans/plan_001/phases/resolve
```

**Response:**

```json
{
  "planId": "plan_001",
  "currentPhase": 1,
  "phaseName": "Foundation",
  "phaseProgress": {
    "total": 5,
    "completed": 3,
    "percent": 60
  },
  "nextTask": {
    "id": "task_004",
    "title": "Set up authentication middleware",
    "blocked": false
  },
  "blockedTasks": []
}
```

**Errors:** `NOT_FOUND` (404)

> [!NOTE]
> Phase resolution considers task dependencies. A task is blocked if any of its dependencies are not yet completed.
