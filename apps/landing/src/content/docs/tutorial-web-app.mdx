# Tutorial: Build a Web App

This tutorial walks you through creating a complete project plan from scratch. By the end, you will have a fully generated blueprint with tasks, execution prompts, and risk mitigation  -- ready to hand off to an AI coding agent.

## What you will build

A project plan for a **real-time collaborative code editor**  -- think Google Docs for code, with live cursors, multi-language support, and conflict-free editing.

> [!NOTE]
> You do not need to build the actual editor. This tutorial covers the planning process. The output is a structured blueprint you can execute with any AI coding tool.

## Prerequisites

| Requirement | Details |
|---|---|
| Node.js | >= 20.0.0 |
| pnpm | >= 9.0.0 |
| An AI provider key | OpenAI, Anthropic, OpenRouter, or OpenCode Go |

## Step 1: Start the Application

Clone the repository and install dependencies:

```bash
git clone https://github.com/orchestra/orchestra.git
cd orchestra
pnpm install
```

Start the development server:

```bash
pnpm dev
```

This launches both the API server and the web frontend. Open your browser to `http://localhost:3001`.

> [!TIP]
> If port 3001 is in use, check the console output for the actual URL. The API runs on port 3000 by default, and the frontend proxies to it automatically.

You should see the Orchestra dashboard with an empty project list.

## Step 2: Create Your First Project

Click **"New Project"** on the dashboard. You will see two input fields and a mode selector.

### Fill in the project details

| Field | Value |
|---|---|
| **Name** | `Collab Editor` |
| **Idea description** | See below |

```
A real-time collaborative code editor that allows multiple developers to edit
the same file simultaneously. Built with CRDT-based conflict resolution for
seamless sync. Features include: live cursor presence showing where other
collaborators are editing, syntax highlighting for 20+ programming languages,
a built-in terminal panel, voice chat for quick discussions, and session
replay to review changes after the fact. Target audience is remote development
teams of 2-10 people. Tech stack: Next.js 15 App Router, Yjs for CRDT sync,
WebSocket connections via Socket.io, PostgreSQL for persistence, Redis for
pub/sub message brokering. Must support files up to 50MB with less than
100ms sync latency. Deployment on AWS with auto-scaling for up to 500
concurrent sessions per instance.
```

### Select interview mode

Choose **Advanced** mode for this tutorial. We want comprehensive coverage since this is a complex project with real-time sync, multiple integrations, and strict performance requirements.

> [!TIP]
> The idea description is 10 -- ,000 characters. Be as specific as possible  -- mention your tech stack, performance targets, user count, and any constraints. The AI uses every detail.

Click **"Create Project"**. Orchestra creates the project and starts the interview session.

## Step 3: Answer the Interview Questions

You are now in the interview. Orchestra presents one question at a time, organized by phase.

### The adaptive flow

Each phase begins with an **intro banner** explaining what the phase covers. For example, the ideation phase intro reads:

> *"First, let's understand your project idea  -- what you're building, who it's for, and what success looks like."*

Click **"Got it"** to dismiss the intro and see the first question.

### Example questions and answers

Here are some questions you will encounter and strong example answers:

**[ideation] What is the core purpose of this project?** `required`

```
A real-time collaborative code editor for remote dev teams. Multiple developers
edit the same file with live cursors, CRDT-based sync, and sub-100ms latency.
Think Google Docs meets VS Code.
```

**[architecture] What tech stack do you prefer?** `important`

```
Next.js 15 App Router, TypeScript, Yjs (CRDT), Socket.io (WebSocket),
PostgreSQL (Prisma ORM), Redis (pub/sub), Tailwind CSS, shadcn/ui.
Monaco Editor for the code editing surface.
```

**[architecture] What is the expected scale?** `important`

```
500 concurrent sessions per instance, auto-scaled on AWS. Each session
supports 2-10 simultaneous editors. Files up to 50MB. Target sync latency
under 100ms for text operations.
```

**[security] What authentication method?** `important`

```
OAuth 2.0 with GitHub and Google providers. JWT sessions with 24-hour
expiry. No password-based auth. API keys for programmatic access with
scoped permissions.
```

**[core-features] What is the most complex feature?** `context dependent`

```
The CRDT-based real-time sync engine. Yjs handles document state, but we
need custom awareness protocol integration for cursor presence, optimistic
UI updates with server reconciliation, and graceful degradation when
connections drop. This is the critical path.
```

### Understanding the adaptive logic

Orchestra's interview engine adapts as you answer:

| Behavior | Description |
|---|---|
| **Category filtering** | Advanced mode asks critical, high-value, optional, and contextual questions. Quick mode skips optional. |
| **Phase progression** | Questions flow through 12 phases: ideation, requirements, architecture, security, database, backend, frontend, core-features, ai-systems, testing, deployment, monitoring |
| **Skip logic** | If you answer "Not sure yet" or give a very short answer, the engine notes the gap and may flag it later |
| **Optional questions** | Marked `[optional]`  -- you can click **"Skip"** without penalty |

> [!NOTE]
> Each question shows a **"Why this matters"** hint below the question text. For example, the core-features question explains: *"The most complex feature determines the critical path in the execution plan."* This helps you understand what level of detail to provide.

### Reaching the end

After answering all questions, you see the **phase summary** screen. It shows how many answers you provided per phase. Ideally, every phase should show at least one answer.

Click **"Generate project plan"** to proceed.

## Step 4: Review and Generate

When you click **"Generate project plan"**, Orchestra transitions the session to `ready_for_generation` and starts the 7-stage pipeline. The progress UI appears inline.

### What happens during generation

```
Stage 1: Analyzing your answers          (1-2s)
  +Building context pack from interview answers

Stage 2: Building project analysis        (2-3s)
  +Running deterministic analysis on synthesized data

Stage 3: Generating project plan with AI  (30-60s)
  +Calling AI provider to generate blueprint and roadmap

Stage 4: Creating roadmap                 (2-5s)
  +Generating phase roadmap from blueprint

Stage 5: Decomposing into tasks           (3-8s)
  +Breaking phases into executable tasks

Stage 6: Assembling execution prompts     (10-30s)
  +Building per-task execution prompts

Stage 7: Generating project summary       (2-5s)
  +Synthesizing project overview and key decisions
```

> [!WARNING]
> Stage 3 (blueprint generation) is the longest. If your provider is slow or rate-limited, you may see an `attempt 2` badge appear  -- Orchestra automatically retries with a fallback model.

### Real-time progress

As each stage runs, you see:

- A **purple pulsing dot** next to the active stage
- **Subtask details** showing which phase or task is being processed
- A **progress bar** (filled when percentage is known, indeterminate otherwise)
- **Elapsed time** counter

When all stages complete, you are redirected to the plan summary page.

## Step 5: Explore Your Blueprint

The plan summary page displays your generated blueprint. Let's walk through each section.

### Metrics bar

At the top, you see:

```
confidence: 72% | phases: 10 | flags: 3 ambiguity items
```

| Metric | What it means |
|---|---|
| **Confidence: 72%** | The AI is fairly confident in the plan based on your answers. Green (>= 60%) is good. |
| **Phases: 10** | Ten project phases were generated (some phases may be merged if not relevant). |
| **Flags: 3** | Three ambiguity items were detected  -- areas where the AI had to make assumptions. |

### Project summary

The project summary section provides:

- **Project overview**  -- a concise description of what you are building
- **Key features**  -- the main capabilities (real-time sync, cursor presence, voice chat, etc.)
- **Technical constraints**  -- your stack choices, latency targets, file size limits
- **Architecture highlights**  -- notable decisions like CRDT-based sync, Redis pub/sub
- **Risk summary**  -- the most significant risks in 1-2 sentences

### Phase progress

Each phase is listed with its status and confidence:

```
+Ideation & Discovery          [sufficient]    85%
+Requirements Engineering      [sufficient]    78%
+System Architecture           [sufficient]    71%
~ Security Planning             [insufficient]   42%
+Database Design               [sufficient]    68%
+Backend Design                [sufficient]    74%
+Frontend Design               [sufficient]    80%
+Core Features                 [sufficient]    65%
+Testing                       [sufficient]    55%
+Deployment                    [sufficient]    70%
```

> [!TIP]
> Phases marked with `~` (insufficient) will produce `needs_review` tasks in the task graph. You can address these later by providing additional input directly in the task detail panel.

### Assumptions and constraints

Scroll down to see:

- **Assumptions**  -- things the AI inferred (e.g., "Assuming WebSocket reconnection with exponential backoff")
- **Constraints**  -- hard limits from your answers (e.g., "Must support files up to 50MB")

### Risks

The risks section lists potential issues:

```
+- CRDT library may not handle 50MB files within latency target
  +source: core-features

+- Voice chat adds significant infrastructure complexity
  +source: ai-systems

+- Auto-scaling to 500 sessions may require custom Redis cluster setup
  +source: deployment
```

Leave these for now  -- you will mitigate them in Step 8.

## Step 6: Navigate the Task Graph

Click **"[ view task graph ]"** at the bottom of the summary page to open the task graph view.

### Layout

Tasks are organized by phase in a timeline view:

```
+IDEATION (2)
  +Set up project repository and CI/CD pipeline
  +Define project structure and monorepo configuration

+REQUIREMENTS (3)
  +Implement user authentication with OAuth 2.0
  +Build session management and invitation system
  +Create user preferences and settings panel

+ARCHITECTURE (4)
  +Configure Next.js 15 App Router with TypeScript
  ...
```

Each task node shows:

- **Status glyph**  -- `+- pending, `+- blocked, `++ ready, `+- complete
- **Title**  -- the task description
- **Type pill**  -- `ai` for AI-generated tasks, `manual` for human-only tasks
- **Dependency count**  -- `+2 deps` or `no deps`
- **Priority**  -- `priority: high`

### Using keyboard navigation

Try the keyboard shortcuts:

| Key | Action |
|---|---|
| `j` | Move down to the next task |
| `k` | Move up to the previous task |
| `Enter` | Select the highlighted task (opens detail panel) |
| `]` | Jump to the next phase |
| `[` | Jump to the previous phase |

Press `j` a few times to move through tasks, then press `Enter` to select one.

### Task detail panel

With a task selected, the right panel shows:

- **Title** and metadata (phase, type, priority, status)
- **Dependencies**  -- clickable list of upstream tasks
- **Acceptance criteria**  -- numbered checklist for the task
- **Blocked by**  -- tasks that must complete first
- **Mark as complete**  -- checkbox to track your progress

> [!TIP]
> Click any dependency in the "Dependencies" section to jump directly to that task. This is useful for tracing the critical path.

### Handling needs_review tasks

If you have phases marked `insufficient`, some tasks appear as `pending_input` type. Select one to see a textarea in the detail panel:

```
+ -- + --  provide additional input (optional)

Describe what's missing for this phase  -- technologies, requirements,
constraints, or any detail that would help the AI generate better tasks...
```

Write a few sentences of context and click **"[ resolve & regenerate tasks ]"**. Orchestra re-runs task generation for that phase with your additional input.

## Step 7: View Execution Prompts

With a task selected in the task graph, click **"→view execution prompt"** at the bottom of the detail panel (or press `p` on the keyboard).

### The 7-section structure

The prompt preview opens with tabbed navigation for each section:

```
[Objective] [Context] [Constraints] [Expected Output] [Validation...] [Architectu...] [Agent Tips]
```

Each section contains targeted information:

| Section | Example content |
|---|---|
| **Objective** | "Implement the CRDT-based real-time sync engine using Yjs with WebSocket transport via Socket.io" |
| **Context** | "The project uses Next.js 15 App Router. Yjs handles document state. Redis manages pub/sub for multi-instance sync." |
| **Constraints** | "1. Sync latency must be under 100ms for text operations\n2. Files up to 50MB must be supported\n3. Must handle 10 simultaneous editors per document" |
| **Expected Output** | "A working sync engine with Yjs integration, WebSocket transport, awareness protocol for cursor presence, and automatic reconnection with state reconciliation." |
| **Validation Criteria** | "1. Two browser clients editing the same document see each other's changes within 100ms\n2. Disconnecting and reconnecting does not lose edits\n3. No merge conflicts in concurrent edits" |
| **Architectural Alignment** | "This task is the critical path of the project. The sync engine must be in place before cursor presence, collaborative editing UI, or session replay can be implemented." |
| **Agent Tips** | Security notes, edge cases (large file handling, memory limits), dependency warnings (Yjs version compatibility), and common bugs (awareness protocol cleanup on disconnect) |

### Copy to clipboard

Click **"[ copy raw ]"** in the prompt header to copy the full prompt as markdown. Paste it directly into your AI coding agent:

```bash
# Example: paste into OpenCode, Claude Code, Cursor, etc.
# The prompt is self-contained with all context needed
```

> [!TIP]
> Each prompt is designed to be **self-contained**. You do not need to provide additional context  -- the prompt includes everything the AI agent needs to implement the task correctly.

## Step 8: Mitigate Risks

Navigate back to the plan summary page (click **"→Back to plan"** or use the breadcrumb).

### Select risks to mitigate

Scroll to the **risks** section. Each risk has a checkbox:

```
++- CRDT library may not handle 50MB files within latency target
++- Voice chat adds significant infrastructure complexity
++- Auto-scaling to 500 sessions may require custom Redis cluster setup
```

Check the risks you want to address. For this tutorial, select all three.

### Trigger mitigation

Click the button at the bottom:

```
[ mitigate selected risks (3) ]
```

### What happens

Orchestra sends the selected risks to the AI, which:

1. Identifies which **phases** are affected by each risk
2. **Rewrites** the phase summaries, narratives, and key decisions to reflect post-mitigation strategies
3. **Updates** execution prompts to include mitigation steps (fallbacks, feature flags, monitoring)
4. Generates a **change summary** describing what was updated

### Review the changes

After mitigation completes, a green banner appears at the top:

```
+PLAN REFINED
Updated 3 phases to address selected risks. Security phase now includes
CRDT performance benchmarks, voice chat is deferred to Phase 2 with a
simplified MVP scope, and deployment phase adds Redis cluster configuration
with auto-scaling policies.
```

> [!NOTE]
> The risks are not deleted  -- they remain in the risks section for reference. The plan itself is updated to account for them. Scroll through the phases to see the updated content.

You can now return to the task graph to see updated execution prompts that include the mitigation strategies.

## Step 9: Export Your Plan

Navigate back to the **task graph** view one final time.

### Export the JSON bundle

Click **"[ →export bundle ]"** in the top-right corner. The browser downloads a file named `prompts-<session-id>.json`.

The bundle contains:

```json
{
  "projectName": "Collab Editor",
  "planVersion": 1,
  "generatedAt": "2025-01-15T10:30:00.000Z",
  "tasks": [
    {
      "id": "task-uuid",
      "title": "Implement CRDT sync engine",
      "phaseType": "core-features",
      "priority": "high",
      "executionPrompt": "## Objective\n...",
      "dependencies": [...]
    }
  ],
  "phases": [...],
  "metadata": {...}
}
```

> [!TIP]
> The JSON bundle is designed for programmatic consumption. Use it to feed tasks into CI/CD pipelines, project management tools, or batch-process prompts through AI coding agents.

### What to do next

You now have a complete project plan. Here are some ways to use it:

| Approach | How |
|---|---|
| **AI-assisted implementation** | Copy individual prompts from the task graph and paste them into OpenCode, Claude Code, Cursor, or Codex |
| **Manual implementation** | Use the phase structure and acceptance criteria as a development checklist |
| **Team coordination** | Share the JSON bundle with your team  -- each task is self-contained with dependencies clearly mapped |
| **Iterative refinement** | Return to the interview to add more detail, then regenerate specific phases |
